# API Explorer Request/Response 区域滚动与布局调整 Spec

## 1. 文档目标

本 Spec 定义 `.worktrees/api-explorer` 中 API Explorer 请求区与响应区的局部交互调整方案。

本次变更不重做 Explorer 整体工作台结构，而是在现有 Postman 风格工作区基础上，修正以下体验问题：

1. 内容区域会随着长文本无限拉长，影响页面整体可读性。
2. 请求区中的子 `section` 仍然保留展开/收起交互，增加了不必要的操作成本。
3. 请求区内的参数输入与请求摘要仍然偏纵向堆叠，不利于同时对照输入与结果。
4. 没有实际内容时，内容块仍然保留占位，造成空白与视觉噪音。

## 2. 背景与现状

当前实现位于以下文件：

- `public/explorer/app.js`
- `public/explorer/styles.css`

当前请求区的主要实现特征如下：

- 参数区与请求摘要都由 `createRequestSection()` 生成。
- `requestSectionState`、`toggleRequestSection()`、`renderRequestSectionState()` 负责折叠状态管理。
- `queryParams`、`pathParams`、`body` 与 `preview` 都被视为可折叠分区。
- `.code-block` 采用 `min-height` + `overflow: auto`，但没有统一的最大高度约束。

当前实现存在的具体问题如下：

- 长响应、长请求摘要和日志详情会把卡片高度持续撑开。
- 折叠按钮与点击 header 展开/收起不符合本轮“默认展开、直接可用”的使用目标。
- 请求区没有把“可编辑输入”和“只读摘要”做稳定的左右分栏。
- 某些无内容场景下仍然保留内容区框体，影响信息密度。

## 3. 目标

本次调整目标如下：

1. 内容型区域统一设置最大高度，超出部分仅在区域内部滚动。
2. 请求区内的 `section` 默认展开，不再展示展开/收起按钮，也不再支持点击折叠。
3. 请求区改为左右布局，左侧承载参数输入，右侧承载请求摘要。
4. 没有内容时，整块内容区域不渲染，不保留空白占位。
5. 保持现有元数据协议、请求发送逻辑和日志记录逻辑不变。

## 4. 非目标

以下内容不在本次范围内：

- 修改 `/explorer/metadata` 返回结构。
- 重构为前端框架组件体系。
- 引入本地持久化的面板布局或折叠状态。
- 改造请求日志的数据结构与记录策略。
- 新增响应语法高亮、Diff 对比或多标签请求页。

## 5. 方案选型

本次采用 `方案 B：结构 + 样式联调`。

### 5.1 推荐方案：结构 + 样式联调

- 在 `app.js` 中移除请求子分区的折叠状态与按钮渲染。
- 在请求区内新增左右两栏容器，分离“输入类内容”和“摘要类内容”。
- 在 `styles.css` 中为代码块和日志详情增加统一最大高度。
- 在渲染层只输出有实际内容的区块。

优点：

- 完整覆盖本次全部诉求。
- DOM 结构更直观，后续扩展更稳。
- 可避免用纯 CSS 隐藏空内容带来的语义噪音。

缺点：

- 比单纯改样式多一点前端渲染逻辑改动。

### 5.2 备选方案：纯样式修补

- 保持现有 DOM 与折叠逻辑，只通过 CSS 伪装默认展开和双栏。

优点：

- 改动小。

缺点：

- 无法真正做到“无内容时整块不渲染”。
- 折叠状态逻辑仍然留在代码中，后续维护成本较高。

## 6. 信息架构调整

### 6.1 Request 面板

`request` 面板内部调整为两列结构：

1. `request-input-column`
2. `request-preview-column`

左列用于承载以下输入型内容：

- 路径参数
- 查询参数
- Body JSON
- 请求为空时的参数空状态

右列用于承载以下只读内容：

- 请求摘要

布局规则：

- 桌面端默认左右布局。
- 窄屏场景回退为上下堆叠。
- 左右列都允许内部内容自然增高，但内容型代码区域需要受最大高度约束。

### 6.2 Response 面板

`response` 面板保留当前卡片结构，但内容预览区改为“受限高度 + 内部滚动”。

### 6.3 Logs 面板

请求日志的详情区与必要时的列表区也遵循相同的高度约束原则，避免日志区域把整个页面无限撑开。

## 7. 渲染规则

### 7.1 请求子分区渲染规则

请求区的子分区遵循以下规则：

- `路径参数`：仅当 `endpoint.pathParams.length > 0` 时渲染。
- `查询参数`：仅当 `endpoint.queryParams.length > 0` 时渲染。
- `Body JSON`：仅当请求方法为 `POST` 时渲染。
- `请求摘要`：仅当存在当前激活接口时渲染。

“无内容时整块不渲染”的定义如下：

- 不创建对应 `section` DOM 节点。
- 不保留边框、留白和空说明文字。
- 不依赖 `display: none` 去隐藏一个原本已经渲染的空块。

### 7.2 参数区容器渲染规则

左列参数区采用如下规则：

- 至少存在一个输入型分区时，渲染参数容器。
- 当当前接口既没有路径参数、也没有查询参数、也不支持 Body JSON 时，不再渲染“参数内容容器”。
- 此时页面只保留顶部接口概览、发送按钮所在主区域，以及右侧有意义的请求摘要。

说明：

- 当前实现中的“当前接口无需额外参数，直接发送请求即可。”空状态文案不再作为独立内容块展示。
- 如果后续需要保留该提示，应将其并入主标题区域的辅助说明，而不是继续占用一个独立内容容器。

### 7.3 默认展开规则

本次调整后，请求区子分区全部视为静态展开：

- 不再显示展开/收起按钮。
- 不再响应点击 header 切换折叠状态。
- 不再维护 `requestSectionState` 这类 UI 折叠状态。
- 不再输出 `is-collapsed` 相关样式状态。

## 8. 布局与滚动规则

### 8.1 内容区域高度约束

以下内容型区域需要统一最大高度：

- 请求摘要代码块
- 响应结果代码块
- 日志详情代码块

必要时也可对日志列表设置上限高度，避免历史记录过多时挤压详情区。

设计原则：

- 卡片本身不作为主要滚动容器。
- 文本内容自身成为滚动容器。
- 高度上限统一，避免不同区块出现明显不一致的视觉节奏。

建议实现范围：

- 桌面端内容区最大高度控制在 `320px` 到 `420px` 区间。
- 移动端可适当放宽，或直接让双栏回退后保持单列自然流式布局。

### 8.2 Request 左右布局规则

请求区内部布局规则如下：

- 左列优先占据更大宽度，用于承载表单输入。
- 右列宽度相对稳定，用于展示请求摘要。
- 当左列不存在任何内容时，右列可独占整行。
- 当屏幕宽度不足时，双列回退为单列纵向布局。

### 8.3 页面级滚动规则

本次仅约束内容型区块的内部滚动，不改变以下现有行为：

- 页面整体仍可自然纵向滚动。
- 左侧接口列表仍保持其自身滚动规则。
- 右侧工作区不额外引入全局固定高度容器。

## 9. 代码改动边界

### 9.1 `app.js`

需要调整的逻辑包括：

- 删除请求子分区折叠状态常量与相关状态字段。
- 删除 `toggleRequestSection()`、`renderRequestSectionState()`、键盘交互和点击事件中的折叠分支。
- 调整 `createRequestSection()`，移除切换按钮与按钮语义属性。
- 调整 `renderRequestConfig()`，引入左右布局容器。
- 按“有内容才渲染”的规则输出参数列和摘要列。

### 9.2 `styles.css`

需要调整的样式包括：

- 请求区双栏网格或弹性布局样式。
- 请求子分区 header 的静态展示样式。
- 删除或废弃 `request-section-toggle-button`、`is-collapsed` 等折叠相关样式。
- 为 `code-block`、日志详情区以及必要的日志列表设置最大高度与内部滚动。

## 10. 风险与兼容性

本次调整的主要风险如下：

- 删除折叠逻辑后，现有与折叠相关的测试需要同步修订。
- 如果请求区 DOM 结构变化较大，选择器可能影响现有测试断言。
- 当左列完全无内容时，右列独占布局需要额外验证视觉平衡。

兼容性原则：

- 不改变请求构造逻辑。
- 不改变 `fetch` 调用链路。
- 不改变接口元数据消费方式。
- 仅改变前端渲染结构与局部交互表现。

## 11. 测试与验证

### 11.1 功能验证

至少覆盖以下场景：

1. 只有查询参数的 `GET` 接口：
   - 左列渲染查询参数。
   - 右列渲染请求摘要。
   - 不显示折叠按钮。
2. 无参数的 `GET` 接口：
   - 参数容器不渲染。
   - 请求摘要仍可单独显示。
3. 带 Body 的 `POST` 接口：
   - 左列渲染 `Body JSON`。
   - 右列实时展示摘要更新。
4. 长响应场景：
   - `Response` 区保持固定上限高度。
   - 页面不因响应文本无限拉长。
5. 长日志详情场景：
   - 日志详情区内部滚动。

### 11.2 自动化测试

建议更新或新增以下测试：

- Explorer 工具函数或页面渲染相关测试，覆盖“无内容时不渲染区块”的逻辑。
- 与请求子分区折叠相关的旧测试需要改为验证“默认静态展开”。
- 布局类样式断言只保留必要范围，避免脆弱的像素级测试。

## 12. 实施结论

本次方案以“默认展开、双栏对照、内容内滚动、空块不渲染”为核心原则，在不修改后端协议和请求链路的前提下，提升 Request/Response 区域的信息密度与调试效率。

实现阶段应优先保证：

1. 请求子分区渲染逻辑清晰。
2. 内容高度约束统一。
3. 小屏回退自然。
4. 相关测试同步更新。
