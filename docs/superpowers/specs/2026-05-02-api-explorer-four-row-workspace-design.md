# API Explorer 四行工作区重构设计

## 1. 文档目标

本设计文档定义 `.worktrees/api-explorer` 中 Explorer 页面的一次结构性重排，目标是将当前“左侧接口列表 + 右侧工作区”的布局改造为更聚焦请求调试主流程的“四行工作区”。

本次调整聚焦以下用户诉求：

1. 顶部菜单保持不变。
2. 第二行变为吸顶工具条，包含方法筛选、可搜索接口选择器和发送按钮。
3. 第三行仅在接口存在参数配置时渲染参数表单。
4. 第四行占满可视区域剩余高度，`Response` 与 `Logs` 按 `70% / 30%` 分栏。

## 2. 背景与现状

当前 Explorer 页面位于以下文件：

- `public/explorer/index.html`
- `public/explorer/styles.css`
- `public/explorer/app.js`

当前布局特征如下：

1. 页面采用 `Sidebar + Workspace` 双栏结构。
2. 左侧侧栏同时承担接口搜索、方法筛选和接口列表选择。
3. 右侧工作区中，请求配置与响应结果被拆成多块卡片。
4. 页面主交互依赖左侧接口列表，顶部没有统一的主操作条。

当前结构与本轮目标的差异主要体现在：

- 接口选择入口分散，不符合“先选接口再请求”的单线流程。
- 左侧侧栏占用较大横向空间，压缩了调试结果区。
- `Response` 与 `Logs` 未组成稳定的底部结果工作台。
- 参数区虽然支持动态渲染，但没有提升为独立的第二层工作带。

## 3. 目标

本次重构的直接目标如下：

1. 将 Explorer 页面收敛为单列四行布局。
2. 用顶部吸顶工具条替代左侧接口列表作为唯一接口入口。
3. 保持现有请求构造、发送和日志记录逻辑不变。
4. 保持参数区“有内容才渲染，无内容则整块不渲染”。
5. 让结果区在桌面端稳定占据主要可视空间，并在区域内滚动而不是撑高整页。

## 4. 非目标

以下内容不属于本次改造范围：

- 修改 `/explorer/metadata` 返回结构。
- 改造成 React 或其他组件框架实现。
- 引入多标签请求页、环境变量切换或历史回放 UI。
- 变更请求日志的数据结构。
- 新增复杂的可视化响应渲染器。

## 5. 方案选型

本次采用 `方案 A：移除左侧接口列表，重建四行单列工作区`。

### 5.1 推荐方案

- 保留第一行 Header。
- 删除原 `sidebar` 结构。
- 新增第二行吸顶控制条，承载：
  - 请求方法筛选
  - 可搜索接口选择器
  - `Send` 按钮
- 将参数区提升为第三行独立区域。
- 将 `Response` 和 `Logs` 收敛为第四行结果工作区。

优点：

1. 和目标布局完全一致。
2. 主操作路径更短，视觉层级更清晰。
3. 横向空间更多分配给调试结果，而不是接口导航。
4. 更符合工具化工作台体验。

缺点：

1. 需要同步调整页面 DOM 和前端绑定逻辑。
2. 原有接口列表相关样式和部分选择逻辑需要清理。

### 5.2 备选方案

保留左侧列表，只在顶部新增一套筛选和搜索控件。

不采用原因：

1. 交互重复。
2. 布局不符合“四行工作区”的明确目标。
3. 视觉焦点仍会被侧栏分散。

## 6. 信息架构

页面改造后按如下顺序组织：

### 6.1 第一行：Header

保留以下内容不变：

- 页面标题
- 页面描述
- 返回首页链接
- 在线文档链接

### 6.2 第二行：Sticky Control Bar

该行是吸顶工作条，滚动时固定在 Header 下方。

包含三个功能区：

1. 左侧：请求方法筛选
2. 中间：支持搜索的接口选择器
3. 右侧：`Send` 按钮

交互规则：

- 方法筛选限制当前可选接口集合。
- 选择器展示当前筛选后的接口，并支持关键字搜索。
- 当前激活接口由顶部选择器唯一决定。
- 若当前接口在筛选后失效，自动切换到筛选结果中的第一个接口。

### 6.3 第三行：Request Params

该区域只在当前接口存在实际参数输入项时显示：

- 路径参数
- 查询参数
- `POST` 请求体

渲染规则：

- 没有任何参数时，不输出整块参数容器。
- 有参数时，使用卡片承载表单分区。
- 分区仍按元数据动态生成。

### 6.4 第四行：Result Workspace

该区域占满剩余可视高度，并设置最大高度约束。

布局规则：

- 左侧 `Response` 占 `70%`
- 右侧 `Logs` 占 `30%`
- 两个面板都在自身区域内滚动
- 页面整体仍允许自然滚动，但主要长内容应留在结果区内滚动

## 7. DOM 调整方案

### 7.1 `index.html`

主要结构变更如下：

1. 删除 `sidebar` 及其内部 `endpoint-list` 交互块。
2. 在 `main.workspace` 中新增：
   - `workspace-toolbar`
   - `workspace-params`
   - `workspace-results`
3. 保留当前接口标题、描述和概要信息，但将其并入主工作区头部。
4. 将 `Response` 与 `Logs` 改为同一行并列布局。

### 7.2 元素职责

保留或新增的关键节点：

- `endpoint-search`：顶部搜索输入
- `method-filter`：顶部方法筛选
- `endpoint-select`：接口选择器
- `send-request`：发送按钮
- `request-panels`：参数区容器
- `response-preview`：最近一次请求结果
- `request-log-detail`：会话日志详情

## 8. 前端逻辑调整

### 8.1 `app.js`

前端逻辑需要做以下调整：

1. 删除对侧栏列表 `endpoint-list`、`endpoint-empty`、`endpoint-count`、`active-endpoint-hint` 的依赖。
2. 增加 `endpoint-select` 的 DOM 查询和渲染逻辑。
3. 将“可见接口集合”的结果渲染到 `select` 选项中，而不是按钮列表。
4. 保留方法筛选与关键字搜索逻辑，但改为直接驱动 `select`。
5. 当 `select` 值变化时切换当前激活接口，并刷新参数区、请求摘要和结果区。
6. 参数区继续遵循“有内容才渲染”的规则。

### 8.2 搜索与选择行为

搜索和选择规则如下：

1. 搜索输入仍匹配接口名、分类和路径。
2. `select` 只显示当前筛选后的接口。
3. 选项文案应同时体现方法、名称和路径，降低误选概率。
4. 当没有匹配接口时：
   - `select` 显示禁用占位项
   - `Send` 按钮禁用
   - 主工作区回到空态

## 9. 样式调整

### 9.1 总体布局

`styles.css` 需要将 `.app-shell` 从双栏改为单列容器，并围绕以下块重新组织：

1. `workspace-overview`
2. `workspace-toolbar`
3. `workspace-params`
4. `workspace-results`

### 9.2 Sticky Toolbar

工具条样式规则：

1. 使用粘性定位。
2. 顶部偏移与 Header 保持呼吸感。
3. 背景保持高透明白底和轻微模糊，避免滚动时内容穿透影响可读性。

### 9.3 Result Workspace

结果区规则：

1. 桌面端使用两列网格。
2. 左列 `minmax(0, 7fr)`，右列 `minmax(280px, 3fr)`。
3. 统一设置结果区最大高度。
4. `Response` 和 `Logs` 面板内部使用 `overflow: auto`。

### 9.4 响应式

在窄屏场景下：

1. 第二行工具条回退为纵向堆叠。
2. 第四行结果区回退为单列。
3. 吸顶行为可以保留，但需要避免遮挡内容。

## 10. 风险与兼容性

主要风险：

1. 由于移除了左侧列表，旧测试中对静态 HTML 的断言需要更新。
2. `select` 的接口切换逻辑必须覆盖“筛选后当前接口失效”的边界。
3. 若没有匹配接口，需要正确处理发送按钮禁用和空态显示。

兼容性原则：

1. 不修改后端接口。
2. 不修改元数据协议。
3. 不修改请求发送行为。
4. 仅重组前端结构、交互入口和样式布局。

## 11. 测试策略

至少验证以下场景：

1. Explorer 静态页面包含新的四行工作区结构关键字。
2. 页面不再输出旧的侧栏接口列表结构。
3. 无参数接口时参数区不渲染。
4. 长响应与长日志内容都在各自面板中滚动。
5. 方法筛选与搜索可联动收敛 `select` 选项。

自动化测试策略：

- 更新 `tests/explorer.routes.test.ts` 中对静态 HTML 的断言。
- 重点验证新结构存在、旧侧栏结构消失。
- 保持服务端路由和元数据测试继续通过。

## 12. 实施结论

本次重构以“顶部统一选择、参数按需展示、结果区稳定占屏”为核心原则，在不改变 Explorer 数据协议和请求链路的前提下，将页面收敛成更适合高频调试的四行工作区。

实施阶段优先保证：

1. 顶部工具条成为唯一接口入口。
2. 参数区严格按需渲染。
3. 结果区按 `70% / 30%` 稳定布局。
4. 静态资源测试同步更新。

## 13. 二次收敛调整

在浏览器实看后，本轮补充以下 UI 收敛要求：

1. 删除 `workspace-toolbar-summary` 整块接口摘要，避免第二行工具条出现双层信息带。
2. 删除工具条中的 `接口选择` 标签文本。
3. 删除方法区顶部说明行和 `显示 x / x` 计数文案。
4. 工具条内部各块改为单行水平对齐，优先保持“筛选 -> 搜索 -> 选择 -> 发送”的工具化节奏。
5. `Response` 与 `Logs` 的两个 `pre` 需要显式设置最大高度，并在自身区域内滚动。
6. 第二行 `section.workspace-toolbar` 继续保持 `sticky`，滚动时稳定吸顶。

### 13.1 DOM 收缩规则

本轮应从 `index.html` 中移除以下节点：

- `div.workspace-toolbar-summary`
- `label[for="endpoint-search"]`
- 方法区中承载 `请求方法` 与计数的 `div.filter-header`

说明：

- 删除后不再在顶部重复展示当前接口名、描述、分类和路径。
- 当前接口由 `select` 当前选项直接表达。

### 13.2 脚本同步规则

`app.js` 需要同步移除以下 DOM 依赖和渲染逻辑：

- `endpointCount`
- `activeEndpointName`
- `activeEndpointDescription`
- `endpointSummary`
- `renderEndpointOverview()`

变更后：

- 搜索、方法筛选、接口选择、发送请求逻辑保持不变。
- 空态处理不再依赖顶部摘要区。

### 13.3 样式规则

本轮样式目标如下：

1. `workspace-toolbar-controls` 在桌面端默认单行对齐。
2. `toolbar-method-group`、`toolbar-select-stack` 和 `toolbar-action-group` 垂直居中。
3. `filter-group` 取消依赖说明行后的额外上边距。
4. `code-block` 增加显式 `max-height`，并保留 `overflow: auto`。
5. 工具条保持 `sticky`，同时收紧垂直留白以减小吸顶后的视觉占用。

## 14. 组合框收敛方案

在第二轮实看后，第二行工具条继续收敛为“左侧单一组合控件 + 右侧发送按钮”。

### 14.1 目标

1. 左侧控件融合方法筛选和接口选择。
2. 方法筛选由按钮组改为下拉框。
3. 中间输入框点击后展开候选列表。
4. 输入框既能直接输入关键字筛选，也能点击候选项选择接口。
5. 参数区 `section` 需要设置最大高度，并在区块内部滚动。

### 14.2 DOM 结构

新的第二行结构应调整为：

1. `select#method-select`
2. `input#endpoint-combobox-input`
3. `div#endpoint-combobox-list`
4. `button#send-request`

其中：

- `method-select` 与组合输入框放在同一个左侧容器中，视觉上视为一个整体。
- `endpoint-combobox-list` 为输入框下拉浮层，不再依赖原生 `select`。

### 14.3 交互规则

组合框交互规则如下：

1. 点击输入框时展开候选列表。
2. 输入时按照“方法筛选 + 关键字”共同过滤接口。
3. 候选列表支持鼠标点击选择。
4. 选择完成后关闭候选列表，并同步当前接口。
5. 当输入失焦且未完成选择时，输入框回退为当前激活接口的展示文案。
6. 当方法变更导致当前接口被过滤掉时，自动切换到过滤结果中的第一个接口。

### 14.4 滚动规则

本轮补充以下滚动约束：

1. `section#workspace-params-section` 设置显式最大高度。
2. 参数区头部固定在卡片顶部，表单区在卡片内部滚动。
3. `Response` 和 `Logs` 的两个 `pre` 继续保持独立最大高度和内部滚动。
